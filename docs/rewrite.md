# State-TTT：基于 Qwen3-VL-8B 的长视频结构化计数模型

> 本文档为方法讲解用。规范性定义以 [README](../README.md)、[ARCHITECTURE](../ARCHITECTURE.md)、
> [DECISIONS](../DECISIONS.md) 为准（规范版本 `state_ttt_qwen3vl8b_slot_memory_delta_v1`，schema 14）。

---

## 一、总体思路

我们的目标是让一个多模态大模型（Qwen3-VL-8B）能**精确回答长视频中的计数类问题**——比如"视频里一共出现了几辆不同的车"、"从第 10 秒到第 30 秒发生了几次转弯"这类需要跨帧追踪、去重、状态判断的问题。

核心困难在于：大模型擅长理解语义和生成自然语言，但**不擅长精确计数**。数数需要结构化的状态管理（谁是谁、什么时候开始、什么时候结束），而不是"大概记得看过几个"。

我们的解法是**在 Qwen 基座旁边挂一套专门管状态的模块**，让两套系统各司其职：

- **Qwen 负责理解语义、生成回答**（"有 5 辆车"这句话由 Qwen 说出来）
- **新增模块负责看视频、维护状态、精确计数**（"5"这个数由确定性模块给出，Qwen 不允许覆盖它）

Qwen 本体的结构和权重路径完全不动（ViT 27 层、Merger、36 层 LLM Decoder、DeepStack 注入点全部保持原样）。新增部分只通过一个残差式插入点接入，对基座的侵入极小。

## 二、新增了什么

在 Qwen 基座之外，我们一共新增了 **10 个模块**，按功能分为三条通路：

### 2.1 视觉通路——跨帧记忆

这条通路只有一个模块，但它是整个方法的核心：

**Fast Adapter + Delta-Rule 记忆 M**：一块可在线写入的矩阵记忆（768×768，约 59 万个值），用于在视频的不同片段（chunk）之间传递视觉信息。它是系统里**唯一在推理时会被修改的东西**——模型权重全程不变，变的只是每个视频自己的这块记忆。每处理一个新视频，记忆归零重新开始。

详细机制见第四节。

### 2.2 结构化状态通路——看视频、维护状态

这条通路负责把视频画面转化为结构化的事实记录，包含以下模块：

| 模块 | 作用 | 参数量 |
|------|------|--------|
| Spatial Slot Encoder | 把每个视频片段的视觉特征拆分成 32 个"对象槽位"，每个槽位对应一个可能的对象 | — |
| Temporal Causal Encoder | 6 层因果 Transformer，跨帧建模对象的时序变化，维护 64 个 tubelet 的 KV 缓存 | 48.4M |
| 观测头组（O1/O2/E1/E2） | 四个头分别输出瞬时计数、对象身份、事件概率、阶段状态四类观测；O2 头另带一个 relevance 分支，判断对象是否问题所指的类别 | 22.3M |
| State Bank | 存储结构化事实记录和检索历史，内嵌两台有限状态机（FSM）做事件判定 | 1.32M |
| Identity Bank | 对象身份去重，判断"这是不是一个新出现的对象" | 0（纯确定性逻辑） |

关键设计：这些模块产出的硬状态（Bank 中的记录、FSM 的状态量）在提交前会断开梯度（detach），不参与反向传播。换言之，**状态管理是确定性的，不靠梯度去"学"怎么数数**。

### 2.3 问答通路——回答问题

这条通路负责理解问题、检索相关状态、给出精确答案：

| 模块 | 作用 | 参数量 |
|------|------|--------|
| Query Encoder | 编码问题文本，输出三个向量：检索目标、算子类型、时间范围 | — |
| Operator Router | 根据问题语义（而非关键词匹配）判断应该用哪种计数算子 | — |
| Time Resolver | 解析问题中的时间信息，确定查询窗口 | — |
| Semantic Retriever | 从历史状态记录中检索与问题相关的条目 | 0（零参数打分器） |
| State Resampler | 把检索结果压缩成 16 个 token 喂给 Qwen，让 LLM 感知当前状态 | 14.72M |
| Deterministic Reader | 精确计数的唯一执行者，纯整数算术，不参与反向传播 | 0（纯确定性逻辑） |

分工原则是 **"Reader 管数，Qwen 管说"**：最终答案中的数字由 Deterministic Reader 给出，Qwen 负责把这个数字组织成自然语言回答，但不允许覆盖 Reader 给出的计数结果。

### 2.4 额外改动

除了上述模块，还有一处非模块级的改动：向 Qwen 的 tokenizer 追加了 5 个特殊 token（`<|state_start|>`、`<|state_pad|>`、`<|state_end|>`、`<|number_start|>`、`<|number_end|>`），词表从 151,669 扩展到 151,674。这些 token 用于在 Qwen 的输入序列中标记状态信息和数字的位置。

## 三、核心机制：Delta-Rule 记忆

这是整个方法最关键的部分，值得展开说清楚。

### 3.1 为什么需要记忆

视频是按片段（chunk）逐个处理的。处理第 5 个片段时，前 4 个片段的视觉特征已经不在了。但计数需要知道"之前见过什么"——比如判断当前画面里的车是不是之前出现过的同一辆。记忆 M 就是用来跨片段传递这种信息的载体。

### 3.2 参数和状态严格分开

这个设计有一个核心约束：**模型参数和记忆状态严格分家**。

- **模型参数**（投影矩阵 P_in、P_out、P_C，以及记忆接口 W_k、W_v 等）：存在 checkpoint 里，由外层优化器更新，所有视频共享。
- **记忆状态 M**（768×768 的 FP32 矩阵）：**不注册为模型参数，不进 checkpoint**，每个视频开始时归零。

零初始化不只是一个初始化选择，而是结构性约束：它保证记忆无法被外层挪用成跨视频的静态存储容量。在回答问题的时刻，记忆里的任何信息**必然是本视频写进去的**。

### 3.3 读取机制

当模型需要利用记忆时（比如判断当前对象是否在之前的片段中出现过），执行以下读取：

1. 用当前视觉特征、当前问题、已有的语义状态三者共同构造一个"token key" K
2. 用 K 去查询记忆 M，得到读出值
3. 读出值经过一个门控（初始值 0.1）缩放后，以残差形式加回原始特征

一个重要性质：**当 M = 0 时（即视频刚开始），读出值恒为零**，前向传播的结果与完全不接记忆模块时完全相同（bitwise 一致）。这意味着记忆模块不会破坏基座的原有能力。

### 3.4 写入机制

每处理完一个视频片段并完成硬提交后，执行一次写入。写入遵循 delta rule：

```
M_new = (1-β) · M_old + Σ η_i · (v_i - M_old · k_i) · k_i^T
```

其中 k_i 和 v_i 由当前片段的 slot 状态（经 stop-gradient）计算得来，η_i 是写入强度门控，β 是遗忘率。

三个关键设计决策：

1. **写入是纯归档操作**。slot 状态在写入路径上全部断开梯度（stop-gradient），写入不会反过来影响编码器的表征学习。编码器只从读取路径和最终的问答损失获得梯度。

2. **唯一带梯度的写入输入是 token key K**。所以外层训练学到的本质上是"记忆的检索几何"——即如何组织信息以便后续检索，以及写入的强度控制。

3. **收缩性由结构保证**。所有的 key 都做了单位化，每个 chunk 的写入强度之和不超过 1，遗忘率 β > 0。这些约束保证了记忆更新的雅可比矩阵算子范数始终 ≤ 1−β，meta 梯度在 8 步截断的计算图上天然收缩，不需要额外的梯度裁剪。

### 3.5 数值安全

- 记忆相关的核心运算全部在 FP32 下执行（显式关闭 autocast），只在残差输出边界转回模型精度
- 两种异常会触发跳过写入：本 chunk 无有效 slot、或写入后 M 出现非有限值。跳过时记忆保持原值，计数器 +1 记录
- 每次写入都产出审计信息（写前/写后的 recall 余弦、写入范数、记忆范数等），可用于事后验证"这次写入到底记住了没有"

### 3.6 两种运行模式

| 模式 | 使用场景 | 行为 |
|------|----------|------|
| online_leaf | 在线推理 / A2 阶段训练 | 无梯度写入，新 M 是计算图的叶节点 |
| meta_linear_recurrence | A5 Meta-TTT 训练 | 有梯度写入，M 带计算图；每 8 个 Support 步截断一次（detach 但保留值） |

## 四、State Bank 与 Identity Bank：确定性状态管理

### 4.1 两套系统的分工

记忆 M 和 Bank 系统承担不同的职责：

- **记忆 M** 负责**可微地传递信息**——它的读写参与梯度计算，外层训练可以学习如何更好地利用它
- **Bank** 负责**确定性地存储事实**——精确计数完全依赖 Bank，不指望可微部分

整条从视频到计数的路径是 **"概率 → 事实 → 数"** 三段式：

```
观测头 O1/O2/E1/E2 → 输出概率（不做阈值判断）
        ↓ detach（断开梯度）
State Bank 硬提交 → 阈值判断、状态跃迁、事实记录
        ↓（回答问题时）
Deterministic Reader → 读取事实 → 输出精确整数
```

### 4.2 State Bank

State Bank 是一个结构化的事实存储，管理四个观测头提交的所有记录。

**核心设计原则**：

- **函数式不可变**：每次写入返回新的状态对象 + 版本号递增，全程在 `@torch.no_grad` 下执行，从不就地修改（in-place），这使得快照和回滚是零成本的
- **幂等与因果**：如果位置编号（position_id）没有前进，只写审计日志不改状态，防止重复提交
- **唯一的可学习组件是 Semantic Projector**（1.32M 参数）：负责把 768 维的原始特征投影到 512 维的检索空间

State Bank 内部嵌入了两台有限状态机（FSM），分别负责两种不同的事件计数。

### 4.3 E1 事件计数 FSM

E1 处理的是"瞬时事件"——比如一次转弯、一次停车。它的状态机有四个状态：

```
armed（就绪）→ active（检测到事件开始）→ 计数+1 并回到 disarmed
                                        → 或者事件消失，回到 armed
disarmed（冷却中）→ 确认事件结束 → 回到 armed
```

关键防护机制：事件完成后必须经过"冷却"状态（disarmed），等到事件性概率降回低位才能重新武装，**防止同一个事件被反复计数**。

### 4.4 E2 区间计数 FSM

E2 处理的是"持续性事件"——比如一段加速过程、一个完整的动作序列。它的状态机是：

```
inactive → active → end_candidate → completed → inactive
```

每一步跃迁都要求**概率阈值和阶段分类两个条件同时满足**，只满足其中一个会记录冲突（conflict）但不改变状态。只有从 `end_candidate` 跃迁到 `completed` 才会让完成计数 +1。

### 4.5 Identity Bank

Identity Bank 专门管理对象身份的生命周期，解决"这个对象是不是之前见过的同一个"问题。

工作方式：

1. **两级确认**：新对象首先进入"候选"（Candidate）状态，连续两个 chunk 都可靠匹配后才晋升为"已确认"（Confirmed）。这能压掉偶然闪现一帧的误检
2. **匹配机制**：用 256 维单位化原型向量做内积匹配，阈值 0.8。当两个候选的匹配分数过于接近（margin < 1e-6）时判定为冲突，不做猜测
3. **老化淘汰**：长时间未匹配的候选会被淘汰（TTL 递减至 0），淘汰时同步清理 State Bank 中的关联记录

重要约束：候选状态的对象不可被检索，只有已确认的对象才会进入问答阶段的检索范围。

**relevance 分数（schema 14 新增）**：光知道"这是几个不同的对象"还不够——问题问的是"几辆车"，被追踪的行人就不该算进去。为此每个身份还携带一个 relevance 分数，回答"这个对象是不是问题所指的类别"。分数由 O2 头以乘性 query 交互计算（`σ(⟨identity, W·q_target⟩)`），并随身份的生命周期一路传递：候选创建时记下初值，之后的每次匹配、晋升、确认都用与原型向量相同的 EMA 方式更新，最终落在已确认身份的记录里，跟着记录一起交给问答阶段。

## 五、问答通路：从问题到答案

### 5.1 总体流程

收到一个问题后，系统需要搞清楚三件事：

1. **查什么**（q_target）——问题在语义空间中对应什么目标
2. **怎么算**（算子类型）——用哪种计数方式
3. **算哪段**（时间窗口）——只看视频的哪个时间范围

然后根据这三个信息去检索相关的状态记录，最后执行计数。

### 5.2 Query Encoder

一个 4 层的双向 Transformer（hidden 768、12 heads），输入是 Qwen 的 4096 维问题 token embedding。经过池化后分成三个独立的 512 维输出头：

- **q_target**：用于检索打分，也注入到 State Resampler、记忆的 key 构造和 O2 relevance 头中
- **q_operator**：用于判断算子类型
- **q_time**：用于解析时间窗口

三个头共享主干、只在最后一层分叉，各有独立的监督信号。

### 5.3 Operator Router

用 9 个可学习原型向量做余弦相似度分类，对应 8 种计数算子 + 1 个"不支持"类别。8 种算子覆盖四个观测头的不同查询方式：

| 算子 | 含义 | 对应观测头 |
|------|------|------------|
| o1-snap | 当前可见数量 | O1（瞬时计数） |
| o1-delta | 相对变化量 | O1（瞬时计数） |
| o2-unique | 累计出现的不同对象数 | O2（身份） |
| o2-gain | 指定时间段内新出现的对象数 | O2（身份） |
| e1-action / e1-transit | 事件发生次数 | E1（事件） |
| e2-periodic / e2-episode | 完成的区间数 | E2（阶段） |

安全设计：置信度门控的阈值当前标注为"需要标定"（`CALIBRATION_REQUIRED`），在标定完成前，**所有低置信度的判断一律归入"不支持"**，不会放行不确定的结果。

### 5.4 Time Resolver

时间窗口解析分为两部分：

- **神经部分**：一个 MLP 对时间模式做 4 分类（now / history / recent / explicit_range）
- **确定性部分**：从问题文本中提取数字 token，按模式构造具体窗口

关键原则：**神经网络只做选择，不做算术**。窗口的具体端点来自问题文本的显式数值，不靠模型去"猜"。解析失败、数值不一致、区间方向反转、超出当前时间等异常情况，一律判定为无效，绝不猜测窗口。

### 5.5 Semantic Retriever

零参数的精确打分器。它读取**当前问题提出前**的状态历史快照（因果约束，防止泄漏），用 Semantic Projector 重新投影后与 q_target 计算余弦相似度。

过滤顺序固定（invalid → 检索不合格 → 未来数据 → 窗口外 → 相似度不足），**不做 Top-K 截断**——因为 Reader 需要看到全部相关记录才能给出正确的计数，截断会静默改变结果。

### 5.6 Deterministic Reader

精确计数的唯一执行者，零参数，纯确定性逻辑。

对于每种算子，它执行的都是简单的整数运算：

| 算子 | 具体做什么 |
|------|------------|
| o1-snap | 直接读取当前可见计数 |
| o1-delta | 当前计数减去基线计数 |
| o2-unique | 数在查询时间前已确认的不同身份数 |
| o2-gain | 数在指定时间窗内首次出现的已确认身份数 |
| e1-action/transit | 读取 FSM 累计的事件计数，或数窗口内的完成时刻数 |
| e2-periodic/episode | 数窗口内的已完成区间数 |

全是整数加减和区间比较，**没有任何概率阈值判断**——阈值在 Bank 的 FSM 里已经判完了。

Reader 的输出有严格的四态约束：

- **ok**：必须附带整数结果
- **empty**：计数为 0 且无相关记录
- **unsupported / invalid**：禁止附带计数值

任何可疑情况（算子和观测头不匹配、记录无效、候选对象泄漏到 Reader 等）都会触发 invalid，**宁可报无效，不给近似值**。

**relevance 闸门（schema 14 新增）**：身份记录带着 relevance 分数到达 Reader 后，o2-unique / o2-gain 两个算子多了一道过滤闸门，有两种模式：

- **audit_only**（当前生产值）：只在审计字段里记录有多少条记录达到了 relevance 阈值，**不改变任何计数结果**
- **enforce**：只统计 relevance 达到阈值的已确认身份；启用前必须先完成阈值标定，配置校验直接拒绝"enforce + 空阈值"的组合

无论哪种模式，完整性校验始终作用于全量记录集——闸门只决定"数哪些"，不放松"查得严不严"。从 audit_only 切换到 enforce 属于显式契约变更，不会静默发生。

### 5.7 State Resampler 与 Reader 的分工

State Resampler（14.72M 参数）是一个 3 层 Perceiver 结构，把检索到的状态记录压缩成 16 个 token 喂给 Qwen。它的职责是**让 LLM 感知状态**，以便生成合适的自然语言回答。

它和 Reader 的分界线很清晰：

| | State Resampler | Deterministic Reader |
|---|---|---|
| 性质 | 可微，参与训练 | 确定性，不参与训练 |
| 作用 | 让 Qwen 理解状态语境 | 给出精确数字 |
| 输出 | 16 个连续向量 → Qwen | 整数 + token ID |

## 六、损失函数设计

### 6.1 顶层结构

最终的训练损失只有两项：

```
总损失 = Answer 损失 + State 损失
```

一个值得注意的地方：**记忆写入路径没有任何直接的损失函数**。记忆接口参数（W_k、W_v、η 门控、β 遗忘率）的唯一梯度来源是问答损失通过计算图的反向传播。换言之，模型学习"怎么写记忆"完全靠"写了之后回答问题的效果"来驱动。

### 6.2 Answer 损失

标准的 shift-by-one token 交叉熵损失（FP32 归约）。

同时计算四个指标（仅监控，不参与梯度更新）：

- teacher-forced token 准确率
- 数字 token 准确率
- 整行精确匹配率
- **Reader 精确计数准确率**（int64 相等比较，硬计数不可导，不进梯度）

### 6.3 State 损失

State 损失由四个等权（权重均为 1.0）组件相加而成，七个子项分布其中：

| State loss 组件 | 子项 | 损失形式 |
|---|---|---|
| **task** | O1 瞬时计数 | 逐 slot 的 6 路 dense BCE |
| | O2 身份 | 身份余弦距离 + 2 路分数 BCE |
| | E1 事件 | eventness / completion / transition 三路 BCE |
| | E2 阶段 | 4 路事件 BCE + 4 分类阶段交叉熵 |
| **operator** | 算子分类 | 9 类交叉熵 |
| **retrieval** | 检索 | 逐记录相似度 logits BCE |
| **time** | 时间解析 | 模式 4 分类交叉熵 + 起始位置指针交叉熵 + 结束位置指针交叉熵 |

其中 task 内部的 O1/O2/E1/E2 按行索引（`row_indices`）互斥分配——每个训练样本只监督一个观测头，行索引不相交。四个观测头损失的基础权重强制为 1，相对权重交给动态平衡器调整；operator / retrieval / time 不走平衡器。

### 6.4 LossTerm 设计

每个损失子项不是一个简单的标量，而是一个结构化对象，包含逐行的有效性掩码和跳过原因。这个设计解决了一个分布式训练中的实际问题：

如果某个 GPU 上的某一行缺少标签，把它按 0 参与均值计算会拉低全局尺度，进而污染后面的 EMA 缩放。通过精确记录哪些行真正有标签，**分母只统计有效行**。

### 6.5 动态平衡器

四个弱监督子项（观测头损失）的权重由一个两级缩放 + 一道封顶的机制动态调整：

1. **第一级（损失量级对齐）**：把每个子项的 EMA 量级拉到和 Answer 损失相当
2. **第二级（梯度量级对齐）**：在激活层面测量梯度 RMS，把各子项拉到几何均值水平
3. **封顶保护**：辅助损失组的总贡献不超过 Answer 损失 EMA 的 40%，保证主目标永远不会被辅助损失盖过

所有统计量都是先做全局归约（一次 all-reduce 打包 12 元统计向量），再计算 EMA 和缩放系数，确保所有 GPU 使用相同的权重。
